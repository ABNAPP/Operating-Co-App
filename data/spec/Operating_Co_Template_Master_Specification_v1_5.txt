0. Dokumentidentitet
Detta dokument beskriver Operating Co Template, en Google Sheets-baserad analys- och värderingsmall för noterade rörelsedrivande bolag. Dokumentet är Master Specification och ska styra metod, modulstruktur, inputs, systemdata, outputs, formler, review rules och bygglogik. Build Specification är ett separat dokument som senare anger exakt hur Apps Script ska bygga flikar, tabeller, named ranges, dropdowns och layout.
Master Specification anger vad mallen ska vara och hur den ska fungera. Apps Script och implementation får dela upp formler i hjälpsteg, men får inte ändra den metodlogik som anges här.
* Dokumentet låser inte celladresser. Celladresser, named ranges och layoutpositioner hör till Build Specification / implementation.
* Om äldre chattar, äldre frameworks eller tidigare build-försök motsäger detta dokument ska v1.5 prioriteras som source of truth.
* Mallen ska byggas som en ren standardmall för Listed Operating Companies, inte som pilotprojekt.
1. Grundidé
Operating Co Template ska analysera och värdera noterade Operating Companies med en Damodaran-inspirerad FCFF/WACC-logik. Mallen ska vara användbar som standardmall: användaren skapar en bolagsflik, fyller manual inputs och modellen räknar live via formler.
Huvudflödet är: Manual Inputs + Google Finance Data where possible + External / Reference Data + Damodaran Data + System Rules -> Forecast & Fade Engine -> Reinvestment & FCFF -> Risk / WACC -> Terminal Value -> Value of Operating Assets -> Firm-to-Equity Bridge -> Equity Value -> Intrinsic Value per Share -> Entry Price / Exit Price / Decision Status -> Company Snapshot -> DashBoard.
Industry-flödet är benchmark-first: Company Sheet -> Selected Damodaran Industrial Benchmark -> Industry Benchmark Config + Damodaran Data -> Engines. Damodaran Industrial Benchmark är mallens branschankare, normaliseringsstöd och sanity-check-system. Det ersätter inte bolagets egna siffror, forecast eller analytisk bedömning.
1. Användaren skapar en ny bolagsflik via Operating Co Tools.
2. Användaren anger Full Ticker.
3. Mallen skapar en ny tom bolagsflik från Operating Co Template.
4. Användaren väljer Selected Damodaran Industrial Benchmark och fyller historiska inputs samt forecast/estimate inputs.
5. Mallen hämtar vissa live/reference data där möjligt.
6. Mallen analyserar bolaget live.
7. Mallen räknar Official Intrinsic Value per Share.
8. Company Snapshot och DashBoard visar official outputs.
2. Metodgrund
Mallen bygger på FCFF till firm, diskonterat med WACC. Official valuation engine är inte en marknadsmultipel, scenario, score eller presentationstabell. Official value kommer från operating cash flows, reinvestment, risk och terminal assumptions.
Table - Official Valuation Chain
This chain defines the official value route in the template.
StepOutputPurpose1Forecast Operating PerformanceRevenue, EBIT, margin, tax and operating assumptions by year.2NOPATEBIT x (1 - tax rate).3ReinvestmentOperating capital required to fund growth.4FCFFNOPAT - Reinvestment.5WACCCost of capital for operating assets.6PV of FCFF + PV Terminal ValueValue of Operating Assets.7Firm-to-Equity BridgeCash, debt, leases, preferred equity, NCI and other claims.8Equity ValueFirm value after bridge adjustments.9Official Intrinsic Value per ShareEquity Value / Selected Diluted Shares.
* FCFF är official valuation engine.
* FCFF diskonteras med WACC.
* Gordon FCFF Terminal Value är official terminal value.
* Firm-to-Equity Bridge tar Value of Operating Assets till Equity Value.
* Selected Diluted Shares används för Official Intrinsic Value per Share.
* MOS, scoring, scenario, sensitivity och multiples får inte ändra Intrinsic Value direkt.
* Multiples, scenario och sensitivity får användas som sanity checks och decision support.
2.1 Implementationstekniska anpassningar
* Tillåtet: dela upp formler i hjälprader, använda named ranges, strukturera inputs i tabeller och låta Apps Script bygga layout automatiskt.
* Inte tillåtet: ändra FCFF-logik, WACC-logik eller terminal value-logik utan stöd i Master Specification eller källmaterial.
* Om en formel eller regel är osäker ska den markeras som oklar och kontrolleras innan den ändras.

5. Build Philosophy
* Build the clean standard template directly.
* Do not build pilot project architecture into the standard model.
* Do not create permanent shadow, gate, readiness or smoke-test layers as core architecture.
* Do not create extra middle layers unless they are required by the specification.
* Build order may be stepwise, but the final base template must include all central modules before calibration starts.
Table - Required Base Template Modules Before Calibration
Module / SheetRequired role before calibrationForecast & Fade RulesRule engine for anchor/fade/stable-state logic.Industry Benchmark ConfigBenchmark-first industry logic, status, stage, cyclicality and display mapping.Damodaran DataReference library for beta, margins, ROC, reinvestment, sales-to-capital, WACC support, tax and sanity multiples.Country Risk / ERPCountry and revenue-weighted ERP support.Riskfree RatesRiskfree rate by valuation currency.FX RatesCurrency conversion and currency review support.Beta EngineCurrent/stable beta support and beta review.Historical DataHistorical trend and base-year support.Reinvestment & FCFFNOPAT, reinvestment and FCFF engine.Risk / WACCCost of equity, cost of debt, weights and WACC path.Terminal ValueGordon FCFF terminal value.Firm-to-Equity BridgeBridge from firm value to equity value.Quality / Review ChecksWorst-flag-wins review architecture.Company Snapshot and DashBoardPresentation/navigation layers.

9. Company Logo & Visual Identity
Company Logo is presentation only. It is based on Company Website / Domain -> Clean Domain -> Logo URL -> Logo Image -> Company Snapshot -> DashBoard. Raw Logo URL is the data source; IMAGE() only displays the image. Missing or broken logo is Info only and must not affect valuation, WACC, FCFF, MOS, Review Flag or Decision Status.

12. Units & Scale Rules
* Financial statement inputs should be entered in millions unless explicitly stated otherwise.
* Per-share items are entered per share.
* Percent inputs should be entered as percentages in Google Sheets, e.g. 10% not 0.10 unless implementation explicitly uses decimal.
* Beta is entered as a normal number, e.g. 1.10.
* Current Price is entered in Trading / Price Currency and converted to Valuation Currency where needed.
* Market Cap should be consistent with the price/share-count logic and documented when manual.

14. Stage Selection & Generalized FCFF Engine
The template uses one generalized FCFF/WACC engine. Stable FCFF, 2-stage FCFF, 3-stage FCFF and n-stage/generalized FCFF are model modes inside the same engine, not separate valuation systems. Stage selection determines Forecast Horizon N, Anchor End Year, Fade Start Year, Stable State Year and Terminal Year.
Table - Model Modes
Model ModeTypical useBenchmark roleStable FCFFMature stable companies with growth near economy and stable margin/ROC.Benchmark is sanity check for stable margin, ROC, beta and reinvestment.2-stage FCFFModerate growth companies that fade to stable state within short horizon.Benchmark supports fade target and terminal reasonableness.3-stage FCFFGrowth companies or margin expansion cases needing explicit anchor plus transition.Benchmark supports transition/fade path and terminal normalization.n-stage / generalized FCFFComplex, negative EBIT, high growth, turnaround or non-linear transition cases.Benchmark supports review and stable-state anchors but does not mechanically decide value.Cyclical normalized FCFFCyclical, commodity or asset-heavy companies far from mid-cycle.Benchmark triggers longer history, normalized base year and mid-cycle checks.Negative earnings / turnaround FCFFNegative EBIT but possible recovery.Benchmark supports target margin and stable economics once ROC is positive.Distress reviewHigh debt / survival-risk cases.Benchmark does not solve distress; review required.
Stage selection should consider: Selected Damodaran Industrial Benchmark + historical stability + forecast support + profitability path + reinvestment needs + risk/WACC + terminal readiness + analyst judgment.

17. Reinvestment & FCFF Engine
Reinvestment is operating capital put back into the business. It is central to FCFF and terminal value. FCFF = NOPAT - Reinvestment. NOPAT = EBIT x (1 - Tax Rate). Growth must be consistent with reinvestment and ROC.
Table - Reinvestment Methods
MethodFormula / logicUse caseDirect MethodCapEx - D&A + Change in Non-Cash Working CapitalUse where company-level data is reliable.Sales-to-Capital MethodChange in Revenue / Sales-to-Capital RatioUse where direct inputs are weak or forecast is revenue-led. Benchmark supports the ratio.Stable MethodTerminal NOPAT x Stable Growth / Stable ROC or Stable Reinvestment Rate = Stable Growth / Stable ROCUse in terminal/stable state only when stable ROC is positive and reasonable.
* Growth = Reinvestment Rate x ROC.
* Reinvestment Rate = Growth / ROC.
* Growth creates value only when ROC > WACC.
* Terminal FCFF must include stable reinvestment.

21. Terminal Value
Official terminal value is Gordon FCFF Terminal Value. Terminal value may start only when stable state is reached or analytically defensible. Stable state requires growth, margin, tax, ROC, reinvestment, beta, WACC, currency and FCFF to be stable or explainable.
Table - Terminal Value Logic
ComponentRuleTerminal FCFFFCFF in first stable year after stable reinvestment.Terminal ValueTerminal FCFF / (Stable WACC - Stable Growth).Stable GrowthNormally linked to long-term nominal growth / riskfree / inflation in Valuation Currency.Stable ReinvestmentMust be consistent with Stable Growth / Stable ROC.Stable ROCMust be positive and economically reasonable before using stable g/ROC.Stable WACCSeparate from Current WACC and WACC by forecast year.Review blockerStable Growth >= Stable WACC makes normal terminal value unsafe / Not Ready.
22. Value of Operating Assets
Value of Operating Assets equals the present value of explicit forecast FCFF plus present value of terminal value. It excludes excess cash, debt, lease debt, preferred equity, minority interest and other non-operating claims that belong in the Firm-to-Equity Bridge.
Table - Value of Operating Assets
Formula componentLogicPV Explicit FCFFSum of forecast FCFF discounted by WACC path.PV Terminal ValueTerminal value discounted to valuation date.Value of Operating AssetsPV Explicit FCFF + PV Terminal Value.
23. Firm-to-Equity Bridge
Firm-to-Equity Bridge converts Value of Operating Assets to Equity Value. Bridge items must not be pushed into FCFF or WACC formulas manually.
Table - Firm-to-Equity Bridge
Bridge itemTypical treatmentCash and cash equivalentsAdd, if excess/non-operating cash or bridge policy includes it.Marketable securities / non-operating assetsAdd if not already part of operating asset value.Gross debtSubtract.Lease debt / lease liabilitiesSubtract or treat as debt-like claims where relevant.Preferred equitySubtract.Minority interest / NCISubtract where relevant.Associates / JVsAdd or adjust separately based on policy and data availability.Options / equity claimsAdjust if material and method supported.Other debt-like claimsSubtract with notes and review.
24. Share Count
Selected Diluted Shares is the denominator for Official Intrinsic Value per Share. The standard chain is Manual Share Count Override if filled; otherwise Market-Implied Shares = Market Cap / Current Price from Google Finance where possible. If market-implied shares are wrong, the user enters a manual override with note. Reported Diluted Shares is not a separate fallback input in the base specification.
Table - Share Count Logic
StepLogic1If Manual Share Count Override is filled, use it.2Otherwise use Market-Implied Shares = Market Cap / Current Price where both are available and currency-consistent.3If neither is available, flag Share Count Review / Not Ready.4Official Intrinsic Value per Share = Equity Value / Selected Diluted Shares.
25. MOS / Entry / Exit / Decision Layer
MOS, Entry Price, Exit Price and Decision Status are decision support. They do not change Official Intrinsic Value per Share. More complex cases, weak data, cyclical normalization, high terminal value share, turnaround logic or severe review flags should require higher margin of safety or stronger review wording.
Table - Decision Layer Outputs
OutputRoleFinal MOSRequired margin of safety based on settings and review context.Entry PricePrice level derived from intrinsic value and MOS.Exit / Target SupportSupport output, not official intrinsic value.Decision StatusPractical decision status based on value, MOS, review and status rules.Status NoteShort explanation of key issue or conclusion.
26. Quality / Review Checks

29. Scenario & Sensitivity
Scenario and sensitivity may be used as support/sanity checks. They must not replace the official FCFF/WACC valuation engine or feed Official Intrinsic Value per Share directly. 30. Financial Health

31. Business Quality
Business Quality is support/review logic. It may evaluate margin stability, revenue durability, ROIC/ROC, reinvestment efficiency, cyclicality, competitive position and data quality. It should not create circular logic that mechanically changes forecast outputs.
32. Assumption Quality
Assumption Quality checks whether user/company assumptions are internally consistent, supported by history, analyst data and benchmark context. The role is to flag assumptions that need review, not to force them to equal industry averages.
* Revenue growth should be plausible vs history, analyst anchors and industry context.
* Margin assumptions should be plausible vs history and Damodaran benchmark support.
* Growth should be funded by reinvestment.
* Stable growth, stable ROC, stable reinvestment and stable WACC must be internally consistent.
* Override inputs require visible notes and review flags.

39. Locked Decisions
9. Official valuation engine is FCFF/WACC -> Value of Operating Assets -> Firm-to-Equity Bridge -> Equity Value -> Official Intrinsic Value per Share.
10. Damodaran Industrial Benchmark is the primary industry anchor and selected directly in the company sheet.
11. ISM-sector is derived display-only information and must not drive engines, review logic or valuation outputs.
12. Industry benchmark supports assumptions and review; it does not mechanically set company forecasts or intrinsic value.
13. Scenario, sensitivity and multiples are sanity/support only.
14. DashBoard is presentation/navigation only, not a valuation engine.
15. Manual inputs belong in manual input areas; engines calculate automatically.
16. FCFF = NOPAT - Reinvestment and terminal FCFF must include stable reinvestment.
17. Stable Growth must be below Stable WACC.
18. Stable Growth / Stable ROC logic cannot be used when stable ROC is <= 0.
19. Current WACC, Stable WACC and WACC by forecast year must be kept separate.
20. Lease liabilities and debt-like claims must be treated consistently in WACC/bridge or flagged for review.
21. SBC is a dilution/risk/MOS/review signal in the base version and should not be added back to FCFF without offsetting treatment.
22. Build Specification remains separate from Master Specification.
