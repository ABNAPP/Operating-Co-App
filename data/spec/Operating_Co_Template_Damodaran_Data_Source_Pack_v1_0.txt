This document is a source pack and control document. It does not replace the valuation model. Official intrinsic value remains driven by company-specific forecast operating performance, NOPAT, reinvestment, FCFF, WACC, present value of FCFF, terminal value, operating assets, equity bridge and intrinsic value per share.

1. How these tables should be used
Damodaran Industrial Benchmark is the model-driving industry anchor. Each company selects a Damodaran Industrial Benchmark directly.
Industry benchmark data provides normalized support for risk, margins, reinvestment, ROC/ROIC, tax, capital structure, cyclicality, forecast/fade and terminal state checks.
Benchmark data should not mechanically set company forecasts. Company data, analyst estimates and manual/company- specific inputs remain primary.
Pricing multiples are sanity checks only. They must not feed official intrinsic value, official entry price or official dashboard valuation outputs.
ISM-sector, if displayed, is only a derived UI/display field and is not part of the data tables below.

2. Required vs support vs sanity-check classification
CategoryMeaningExamples
Core requiredNeeded for the base valuation engine to function properly or to calculate/validate key official drivers.Beta, sales-to-capital, reinvestment, margin, ROC/ROIC, tax, cost of debt.
Core supportNot always directly used as a formula input, but materially supports WACC, FCFF, fade or terminal-state logic.Industry cost of capital, working capital, debt breakdown, industry tax, standard deviations.
Strong supportImproves robustness, quality checks and fade/terminal discipline, but can be added after base import.Historical growth, fundamental EBIT growth, lease capitalization, R&D, total beta.Pricing sanity onlyUsed only to compare valuation output to market pricing. Never drives official intrinsicPE, EV/EBITDA, EV/Sales, PBV, market cap decile multiples.
CategoryMeaningExamplesvalue.Optional governance/supportCan be stored for context or later review modules, but not required for the base template.Insider/institutional ownership and similar data.

3. Module dependency map
Template moduleWhat it needsRelevant tables
Industry Benchmark ConfigDamodaran Industrial Benchmark list; allowed/excluded/special review status; default stage; cyclicality; history recommendation; asset intensity.Raw industry list, beta table, margin table, capex/sales-to-capital, working capital, ROIC, growth tables.Beta EngineUnlevered beta, cash-adjusted unlevered beta, D/E ratio, selected current/stable beta support.Beta, Unlevered beta and other risk measures; Total Beta only as optional risk support.
Risk / WACC EngineCost of equity, cost of debt, tax, capital structure, benchmark WACC sanity.Cost of equity and capital; beta table; debt breakdown; synthetic rating; marginal tax rates; standard deviations.
Reinvestment & FCFF EngineDirect reinvestment, sales-to-capital fallback, working capital, stable reinvestment checks.CapEx/Sales-to-Capital; Working Capital; Fundamental EBIT Growth; Profit Margins; ROIC table.
Forecast & Fade RulesForecast reasonableness, stage support, cyclicality, growth/margin/reinvestment/ROC fade.Margins; historical growth; sales-to-capital; ROIC; working capital; standard deviations; industry config.
Terminal Value EngineStable growth, stable margin, stable ROC, stable reinvestment, stable WACC and terminal readiness.Margins; ROIC; tax; WACC/cost of capital; capex/sales-to-capital; working capital.
Quality / Review ChecksFlags for missing data, outlier assumptions, excessive terminal value, growth without reinvestment, beta/cost-of-debt issues.All core and support tables; pricing multiples only as sanity checks.DashBoardDisplays official outputs and selected industry; does not calculate valuation.Selected Damodaran Industrial Benchmark; ISM display map only if used; final company outputs.

6. Synthetic rating lookup - required structure
The synthetic rating table should be implemented as a reference table, not as hidden logic. The model should choose the correct lookup set based on company type and then map interest coverage to rating and default spread.

TypeFieldPurpose
Input
Firm type1 = large manufacturing/non-financial, 2 = smaller or riskier, 3 = financial service. Operating Co base normally uses 1 or 2; financial service is outside standard Operating Co valuation.
Input
EBITCurrent EBIT used to calculate interest coverage. For operating companies this should be operating EBIT; financial firms have special treatment.InputInterest expenseCurrent interest expense used in interest coverage.InputLong-term government bond rateUsed with default spread to estimate cost of debt.OutputInterest coverage ratioEBIT / Interest expense.OutputEstimated bond ratingMapped from interest coverage lookup table.OutputEstimated default spreadMapped from rating/spread table.OutputEstimated cost of debtRisk-free / long-term government bond rate + estimated default spread.

7. Missing or separate data sources
The supplied tables cover most of the industry benchmark data needed for the Operating Co Template. The following items are still separate requirements for the full workbook data architecture:

Data source / tableWhy it is needed
Country Risk Premium / Equity Risk Premium tableNeeded if the template will calculate weighted ERP by country/revenue exposure. The cost-of-capital table includes an equity risk premium assumption, but not the full country ERP/CRP table needed for country exposure logic.
Risk-free rates by valuation currencyNeeded for selected risk-free rate and WACC by valuation currency. This is a separate system table, not one of the Damodaran industry benchmark tables pasted here.
FX rates / currency mapNeeded for Reporting Currency, Valuation Currency and Trading / Price Currency conversion. Separate from Damodaran industry benchmark data.
Companies in each industry (indname.xls)Referenced in every Damodaran table. Useful for source audit and industry composition review, but not required to calculate company valuation if benchmark data is already imported.
Variable definitionsReferenced in every Damodaran table. Should be kept as a source link so terms such as invested capital, ROIC, D/E and lease adjustments are interpreted consistently.
Conclusion: for the base Operating Co valuation engine, the most important Damodaran industry benchmark tables are beta/unlevered beta, cost of capital, capex/sales-to-capital, working capital, margins, ROIC/ROC, tax, debt/cost of debt support and synthetic rating/default spreads. The remaining tables should be stored as support or sanity-check data where useful, but they should not override official FCFF/WACC valuation logic.
